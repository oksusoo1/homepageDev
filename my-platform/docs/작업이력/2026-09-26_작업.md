# 2026-09-26 작업 — 보안 구조 전환 ③ 사장님 편집·생성·게시판·요청 서버화

관련: [플로우](../플로우.md) · [테이블명세](../db/테이블명세.md)

## 무엇을
브라우저 supabase insert/update/delete/upsert를 없애고, 남은 쓰기를 Server Action + service role로 옮김. 조회·RLS·공개범위 게이트는 그대로(④⑤).

## 왜
클라이언트가 customerId·status·author_type을 보내면 위조 가능.

## 영향 범위
- **DB**: 스키마 변경 없음
- **본사** `/platform`: `createSite`에 주소 규칙·`makeSiteCode` 적용
- **고객** `/my` · `/setup` · `/login` 가입·탈퇴
- **admin/에디터/게시판** `/s/...`
- **게이트**: 방문자 글쓰기는 공개 단계만 (조회 게이트 구조는 불변)
- **테스트**: S8~S13 추가

## 주체 UX
사장님 `/setup` — 주소가 짧거나 예약어면 그 자리에서 안내. 직원 `/platform` 개설도 같은 규칙.

## 보고
- content 상한: `CONTENT_JSON_MAX_BYTES` = 200KB
- HTML 렌더: `dangerouslySetInnerHTML` 0건 (수정 안 함)
- 비밀글: `is_private` boolean만. 비밀번호 없음. 공개 페이지는 제목·본문 숨김
- 탈퇴: 유료 구독이면 `withdraw_at`+구독 해지예약. 아니면 사이트 `suspended` + `customers.status=withdrawn`. 재활성화는 customers.status만
