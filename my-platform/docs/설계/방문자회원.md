# 방문자(손님) 회원 설계

상태: 설계 확정, 구현 전 (보안 전환 ⑤단계 이후 진행)

## 1. 목적
가게 사이트(예: 마곡카페)의 손님이 그 사이트에 가입·로그인해서
문의·비밀글 작성, 본인 비밀글 열람을 할 수 있게 한다. 아임웹의 사이트별 회원과 같은 개념.

## 2. 사용자 구분
| 사람 | 플랫폼 | 가게 사이트 |
|---|---|---|
| 사장님 | customers (구독 고객) | 소유자 — 비밀글 전체 열람, 공지 작성 |
| 손님 | 없음 | 회원 (user_members) |
| 다른 가게 사장님이 가입 | customers (자기 가게) | 회원 |
| 본사 직원 | staff | 열람만 |

## 3. 구조
- 로그인 계정: Supabase Auth 하나 (통합 계정)
- 사이트별 가입 기록: `user_members` 테이블 1개, site_id로 구분 (사이트별 테이블 생성 금지)
- 소유자는 user_members에 저장하지 않는다. `sites.customer_id`가 단일 기준.
  회원 목록 화면에서 user_members + 소유자를 합쳐 "소유자" 배지로 표시

### user_members (안)
| 컬럼 | 의미 |
|---|---|
| user_member_id | PK |
| site_id | → sites |
| auth_id | → auth.users |
| name | 이름(닉네임), 필수 |
| phone | 선택 |
| marketing_agreed_at | 마케팅 수신 동의 시각 (선택 동의) |
| privacy_agreed_at | 개인정보 수집·이용 동의 시각 (필수) |
| status | active / blocked / withdrawn |
| use_flag, created_at, updated_at | 공통 |
- UNIQUE (site_id, auth_id)

## 4. 로그인 입구
- 플랫폼 로그인 `/login`: 사장님·직원용 (현행)
- 가게 사이트 로그인 `/s/{siteCode}/login`, 가입 `/s/{siteCode}/join`: 손님용
- **손님 경로에서는 customers 행을 절대 생성하지 않는다** (현재 /login은 로그인 시 customers 자동 생성)
- 로그인 쿠키는 사이트(호스트)별로 분리하는 방향. 한 가게 로그인이 다른 가게·플랫폼 관리 화면에 이어지지 않게.
  커스텀 도메인은 원래 호스트별이므로 일관됨. 세부는 구현 시 확정

## 5. 가입
- 필수: 이메일, 비밀번호, 이름, 만 14세 이상 확인, 개인정보 수집·이용 동의
- 선택: 전화번호, 마케팅 수신 동의 (필수 동의와 분리)
- 이미 Supabase 계정이 있는 사람(다른 가게 회원·사장님)이 가입하면: 로그인 후 동의 → user_members 행만 추가
- 사이트별 개인정보처리방침 페이지 필요 (사장님=개인정보처리자, 플랫폼=수탁자). 문구는 구현 시 확인

## 6. 로그인 방식
- 1차: 이메일/비밀번호
- 2차: 카카오 (카카오 비즈앱 전환 후. 사이트 주소별 리다이렉트 등록 관리 필요)
- 네이버: 미정 (Supabase 기본 미지원)

## 7. 사장님 회원 관리
- 1차: 회원 목록, 검색, 차단(status=blocked)
- 나중: 엑셀 내보내기 (개인정보 반출 기능이라 신중히)

## 8. 탈퇴
- 사이트 단위: 해당 사이트 user_members만 withdrawn. Supabase 계정은 다른 사이트 가입이 있을 수 있어 유지

## 9. 비밀글 연동
- user_posts에 작성자 계정 컬럼(보안 전환 ④단계에서 추가) 사용
- 열람: 사장님 전체 / 로그인 작성자 본인 / 그 외 "비밀글입니다"
- 비로그인 작성 비밀글은 사장님만 열람

## 10. 구현 시 결정할 것
- 로그인 쿠키 범위 최종 확정
- 차단된 회원의 기존 글 처리
- 개인정보처리방침 문구·동의 기록 보관 방식
