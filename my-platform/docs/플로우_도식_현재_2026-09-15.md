## 1. 큰 그림 — self / managed

```mermaid
flowchart LR
  Start([가입]) --> Choose{제작 방식}

  Choose -->|self 직접| A1[사이트 만들기]
  A1 --> A2[편집]
  A2 --> A3[고객이 배포]
  A3 --> A4[체험 trial]
  A4 --> A5[카드 → 구독]

  Choose -->|managed 대리| B1[제작 문의]
  B1 --> B2[견적·선금]
  B2 --> B3[본사 제작]
  B3 --> B4[미리보기·잔금]
  B4 --> B5[결제수단·서비스 시작]
  B5 --> A4
```

- **self**: 문의(`inquiries`) 없음. 사이트·구독만.
- **managed**: 문의(제작·결제 진도) + 사이트 + (시작 후) 구독.

```mermaid
flowchart LR
```

## 4. 루트 B — 본사 대리 (managed) 시간순

```mermaid
sequenceDiagram
  participant 고객
  participant 문의 as inquiries
  participant 사이트 as sites
  participant OTP as one_time_payments
  participant 구독 as subscriptions

  고객->>문의: 접수 received
  Note over 문의: reviewing 견적(dev_fee_total)
  Note over 문의: 선금 확인 → building + down_paid_at
  Note over 사이트: draft / pending 생성
  Note over 사이트: 검수용 → review + live
  Note over 문의: review (미리보기·잔금)
  고객->>OTP: 잔금 입금신청 → pending_confirm
  Note over 문의: status는 review 유지
  Note over 문의: 잔금 확인 → approved + final_paid_at
  Note over OTP: paid
  고객->>사이트: 서비스 시작 deploySite
  Note over 사이트: published + live + trial_*
  Note over 구독: trial
  Note over 문의: done
```

### 단계별 필드 (정방향)

| 시점 | inquiries | sites | OTP(dev_fee) | subscriptions |
|------|-----------|-------|--------------|---------------|
| 접수 | `received` | (없을 수 있음) | — | — |
| 견적 | `reviewing` | — | — | — |
| 선금 후 제작 | `building` + `down_paid_at` | `draft` / `pending` | — | — |
| 미리보기 | `review` | `review` / `live` | — | — |
| 잔금 신청 | `review` | (유지) | `pending_confirm` | — |
| 잔금 확인 | `approved` + `final_paid_at` | (유지) | `paid` | — |
| 서비스 시작 | `done` | `published` / `live` | — | `trial` |

게이트: `final_paid_at` + `status === 'approved'` 일 때 서비스 시작 가능 (`lib/managed-flow.js`).

## 5. 고객에게 보이는 문의 스텝 (위저드)

코드: `INQUIRY_CUSTOMER_STEPS` (`lib/payment/one-time.js`)  
공통코드 `done`은 위저드에 없고, `done`이면 `/my` 문의 카드 숨김.

```mermaid
flowchart LR
  s1[1 접수완료] --> s2[2 검토/견적]
  s2 --> s3[3 제작중]
  s3 --> s4[4 미리보기·잔금]
  s4 --> s5[5 서비스 시작 준비]
```

실무 체감은 대략 4칸에 가깝다: `접수·견적 → 제작 → 미리보기·잔금 → 시작·운영`.

## 6. 이름·라벨이 헷갈리는 지점

```mermaid
flowchart TB
  subgraph 동명이인["같은 영문코드, 다른 도메인"]
    R1["sites.review = 검수용 공개"]
    R2["inquiries.review = 잔금 단계"]
    B1["deploy.building = 빌드 파이프"]
    B2["inquiries.building = 본사 제작중"]
  end

  subgraph 라벨["같은 코드, 화면마다 다른 한글"]
    L1["공통코드: 고객검수·잔금"]
    L2["고객 UI: 미리보기·잔금"]
    L3["본사 select 등: 검수대기 등"]
  end
```

프로세스가 길이로만 복잡한 것이 아니라, **축이 여러 개 + 라벨 소스 분산**이 겹친다.
