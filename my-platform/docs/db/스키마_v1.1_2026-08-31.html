1. 인증 3계층

auth.users (Supabase 내장) ← 비밀번호·세션 │ ├── auth_id ──► customers ← /login 회원가입 시 자동 INSERT │ └── auth_id ──► staff ← 수동: UI Add user + SQL INSERT
구분테이블계정 생성프로필 생성로그인 후
고객customers /login 회원가입 자동 /my
본사 직원staff Supabase UI Create user SQL INSERT (수동) /platform (role=platform_admin)
주의: UI에서 Create user만 하면 auth.users만 생깁니다. staff INSERT 없이는 /platform 접근 불가, 로그인 시 "프로필 없음" 처리됩니다.

2. 관리자 등록 절차 (2단계)

  1. Supabase → Authentication → Users → Create user (이메일·비밀번호, Auto confirm 체크)
  2. 생성된 사용자 UUID 복사
  3. SQL Editor: 
    INSERT INTO staff (auth_id, email, name, role)
VALUES (
  'ef81303c-....',           -- auth.users.id
  'admin@myplatform.com',
  '관리자',
  'platform_admin'           -- role 컬럼 값 (name 아님)
);

이미 등록된 auth_id로 다시 INSERT 하면 duplicate key 에러 → 정상(이미 등록됨). SELECT * FROM staff; 로 확인.

3. 코드 연동 (lib/auth.js)

함수역할
getAuthCustomer()로그인 + customers 조회
getAuthStaff()로그인 + staff 조회 (status=active)
isPlatformAdmin()staff.role === 'platform_admin' → /platform 허용
getPostLoginPath()로그인 후 이동: admin→/platform, customer→/my, 없으면 null

로그인 분기 (app/login/page.js)

signInWithPassword 성공 → getPostLoginPath() ├─ staff.platform_admin → /platform ├─ customers 있음 → /my └─ 둘 다 없음 → signOut + "프로필 없음" 에러

관리자 콘솔 (app/platform/page.js)

isPlatformAdmin() 실패 시 /login 리다이렉트.

4. staff 테이블

컬럼타입설명
staff_idUUID PK
auth_idUUID UNIQUE NOT NULL→ auth.users
emailVARCHAR(200) UNIQUE
nameVARCHAR(100)
roleVARCHAR(30)platform_admin / support / viewer
statusVARCHAR(20)active / suspended / left

MVP: role=platform_admin, status=active 만 /platform 접근.

5. RLS (Row Level Security)

  • RLS 켜기 = DB가 정책(Policy)을 검사함
  • Run 버튼 = SQL 실행일 뿐, 자동으로 "자기 것만" 보이지 않음
  • 현재 정책: USING (true) → MVP 개발용, 전 행 허용
  • 실서비스 전: auth_id = auth.uid() 등으로 강화 예정
