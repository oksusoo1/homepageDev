v1.2 변경 요약 (v1.1 대비)
  • 주체 용어 확정: customers=고객 · staff=직원 · user=사용자(방문자)
  • 공개 사이트 전용 테이블만 user_ 접두: user_posts, user_messages
  • posts → user_posts (PK post_id 유지, URL 호환)
  • user_messages 신설 — 사용자→고객 문의 (/s/.../contact)
  • support_tickets = 고객→직원 수정요청만 (/my)
  • inquiries = 고객→직원 제작의뢰 (이름에 "문의" 있어도 제작 플로우)

1. 주체 용어

영문(코드/DB)한국어누구
customers고객사장님(소상공인) — 플랫폼의 고객
staff직원본사(플랫폼) 직원
user (접두)사용자공개 사이트 방문자(손님)

2. 메시지·요청 테이블 구분

테이블방향역할UI
user_messages사용자 → 고객방문자 문의/s/{siteCode}/contact
user_posts고객 작성 / 사용자 열람사이트 게시판/s/{siteCode}/board
support_tickets고객 → 직원사이트 수정 요청/my/{subdomain} 수정요청
inquiries고객 → 직원본사 제작 의뢰/my 제작문의

4b. 문의 게시판 UI

  • 사용자: /s/{siteCode}/contact — 목록 + 등록(공개/비공개)
  • 고객: /my/{subdomain} 「방문자 문의」탭 — 전체 열람·답변

5. 관계 개요

sites ├── user_posts (1:N) 게시판 ├── user_messages (1:N) 방문자 문의 ├── support_tickets (1:N) 수정요청 (customers도 FK) └── inquiry_id ──► inquiries (제작의뢰, 선택) customers ├── sites, subscriptions, payments... ├── support_tickets └── inquiries
