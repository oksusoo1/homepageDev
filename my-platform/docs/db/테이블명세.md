# 테이블 명세

작성일: 2026-09-19 · 갱신: 2026-09-25  
**기준: 실DB** + 컬럼 COMMENT (`019_column_comments.sql`)  
관련: [플로우](../플로우.md) · [ERD](ERD.md)

> 아래 **의미** 열 = DB `COMMENT ON COLUMN` 과 동일. Table Editor에서도 확인 가능.

---

## 규칙

- PK: `테이블명_id` (예외: `user_posts.post_id`)
- `site_id`=UUID · `site_code`=문자열 (혼용 금지)
- `use_flag`: **1=사용 · 0=삭제** (조회 기본 1)
- 주체: **customers**=고객(사장님) · **staff**=직원 · **user_***=방문자 (사장님 화면에서는 "고객"으로 표시)

## 1. customers

고객(사장님) 프로필. `auth.users`와 `auth_id`로 연결.

| 컬럼 | 타입 | 의미 |
|------|------|------|
| customer_id | UUID PK | PK |
| email | VARCHAR(200) UNIQUE NOT NULL | 로그인·연락 이메일 |
| name | VARCHAR(100) NOT NULL | 고객 이름 |
| phone | VARCHAR(50) | 연락처 |
| status | VARCHAR(20) | 계정 상태: `active`(정상) \| `suspended`(정지) \| `withdrawn`(탈퇴) |
| created_at | TIMESTAMP | 생성 시각 |
| updated_at | TIMESTAMP | 수정 시각 |
| auth_id | UUID UNIQUE | Supabase Auth 사용자 ID → auth.users |
| use_flag | SMALLINT | 1=사용 · 0=삭제 |
| withdraw_at | TIMESTAMP | 탈퇴 예약일. 미래=잔여기간 대기(로그인 가능), 과거=청구 배치에서 withdrawn 처리 |

| status | VARCHAR(20) | `unpaid` \| `pending_confirm`(입금확인대기) \| `paid` |
| note | TEXT | 메모·안내 |
| paid_at | TIMESTAMP | 납부 확인 시각 |

| use_flag | SMALLINT | 1=사용 · 0=삭제 |

## 7. subscriptions

월 구독·청구 일정. **체험/구독/정지는 `sites.status`.** (status 컬럼 없음)

| 컬럼 | 타입 | 의미 |
|------|------|------|
| subscription_id | UUID PK | PK |
| customer_id | UUID NOT NULL FK | 고객 → customers |
| site_id | UUID NOT NULL FK UNIQUE | 사이트 → sites (사이트당 1) |
| amount | INTEGER | 월 구독료(원). 기본 30000 |
| billing_day | INTEGER | 매월 청구일 (1~28) |
| payment_method | VARCHAR(20) | `manual`(계좌) \| `card`(자동카드) |
| started_at | TIMESTAMP | 구독 행 시작 시각 |
| next_billing_date | DATE | 다음 청구일 |
| cancelled_at | TIMESTAMP | 해지 요청(예약) 시각 |
| created_at | TIMESTAMP | 생성 시각 |
| updated_at | TIMESTAMP | 수정 시각 |
| cancels_at | TIMESTAMP | 서비스 종료 예정일. 경과 시 sites→suspended |
| depositor_name | VARCHAR(100) | 계좌이체 입금자명 |
| bank_transfer_agreed_at | TIMESTAMP | 계좌이체 약정 시각 |
| use_flag | SMALLINT | 1=사용 · 0=삭제 |

청구 대상: `sites.status` ∈ trial\|subscribed **그리고** `cancelled_at` IS NULL

## 11. user_boards

고객(방문자) 사이트 게시판 정의. 사이트당 여러 개. **`board_type`이 동작을 결정** (`lib/user-board.js`).
새 사이트 INSERT 시 트리거로 `공지사항(notice)` · `문의하기(qna)` 자동 생성.

| 컬럼 | 타입 | 의미 |
|------|------|------|
| user_board_id | UUID PK | PK |
| site_id | UUID NOT NULL FK | 사이트 → sites |
| board_key | VARCHAR(50) NOT NULL | URL 식별자 (사이트 내 유일). `/s/{code}/board/{board_key}` |
| name | VARCHAR(100) NOT NULL | 게시판 표시명 (사이트 상단 메뉴) |
| board_type | VARCHAR(20) | `notice`(공지·사장님만 작성) \| `qna`(문의·연락처 필수·비밀글·답변 필요) \| `general`(일반·고객 작성) |
| sort_order | INTEGER | 메뉴 정렬 (작을수록 앞) |
| use_flag | SMALLINT | 1=사용 · 0=삭제 |
| created_at | TIMESTAMP | 생성 시각 |
| updated_at | TIMESTAMP | 수정 시각 |

UNIQUE (`site_id`, `board_key`) WHERE `use_flag = 1`

## 16. support_ticket_messages

고객 요청 대화 — **사장님 ↔ 직원**. 직원 답변·내부 메모가 모두 여기 쌓인다.

| 컬럼 | 타입 | 의미 |
|------|------|------|
| ticket_message_id | UUID PK | PK |
| ticket_id | UUID NOT NULL FK | 요청 → support_tickets |
| author_type | VARCHAR(10) | `customer`(사장님) \| `staff`(직원) |
| author | VARCHAR(100) | 작성자 표시명 |
| content | TEXT NOT NULL | 대화 내용 |
| is_internal | BOOLEAN | true=**직원 내부 메모** (고객 조회 쿼리에서 제외). 직원 글만 가능 |
| read_at | TIMESTAMP | 상대방이 읽은 시각. NULL=안 읽음 → 알림·뱃지 대상 |
| use_flag | SMALLINT | 1=사용 · 0=삭제 |
| created_at / updated_at | TIMESTAMP | 작성 · 수정 시각 |

- 화면에서 **내부 메모는 입력칸 자체가 분리** (체크박스 금지 — 오발송 방지)
