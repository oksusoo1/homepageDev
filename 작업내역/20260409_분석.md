  3. Supabase 연동 방식

  ┌─────────────┬──────────────────────────────────────────┬──────────────────────────────────────────┐
  │    영역     │               연동 테이블                │                   방식                   │
  ├─────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
  │ 로그인      │ auth.users + customers                   │ signUp/signIn → customers INSERT         │
  ├─────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
  │ 사이트 생성 │ sites + subscriptions                    │ setup에서 동시 INSERT                    │
  ├─────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
  │ 에디터 저장 │ sites.content (JSONB)                    │ UPDATE content + 연락처                  │
  ├─────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
  │ 배포        │ sites                                    │ status='published', deploy_status='live' │
  ├─────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
  │ 게시판      │ posts                                    │ SELECT/INSERT (site_id 기준)             │
  ├─────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
  │ 문의        │ support_tickets                          │ INSERT (방문자 → 티켓 생성)              │
  ├─────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
  │ 결제        │ customer_payment_methods + subscriptions │ 카드 등록 후 UPDATE                      │
  ├─────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
  │ 관리자      │ 전 테이블                                │ SELECT/UPDATE (필터링)                   │
  └─────────────┴──────────────────────────────────────────┴──────────────────────────────────────────┘

  Supabase 클라이언트: anon key만 사용 (client-side), API route에서만 service role key 사용

  4. 현재 동작하는 플로우

  가입 → 템플릿 선택 → 기본정보 입력(setup) → 에디터 편집
    → 배포(published) → 체험 14일 시작 → 카드 등록 → 구독 활성화

  - 방문자: preview/[domain] → 히어로 + 연락처 + 게시판 + 문의폼
  - 관리자: platform/ → 사이트/구독/티켓/1회성결제 관리

  6. 아키텍처 평가

  잘 된 점 ✅

  - 명확한 플로우: 가입 → 설정 → 편집 → 배포 → 결제 순서가 자연스러움
  - Server Component 활용: 방문자 페이지(preview)를 서버 컴포넌트로 → SEO 유리
  - 멀티테넌트 라우팅: middleware로 서브도메인/커스텀 도메인 처리
  - 체험 기간 설계: trial 14일 → 구독 전환 구조가 비즈니스 모델에 적합

  개선 필요 ⚠️

  - 컴포넌트 분리 부족 (페이지당 1파일에 모든 로직)
  - 상태 관리 없음 (useState 나열식)
  - 스타일링 혼재 (인라인 + Tailwind)
  - 공통 컴포넌트/디자인 시스템 없음
  - 에러 핸들링 불일치 (일부 try-catch, 일부 무시)

  Phase 3: 결제/운영

  13. 토스페이먼츠 실결제 연동 (MOCK → 실서비스)
